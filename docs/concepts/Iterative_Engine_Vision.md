# Iterative Engine Vision: The Multi-Stroke Paradigm

## 1. The Philosophy of the "Piston"
A single pass (Iteration 1) of the 9D Strategic Engine acts as a "Single Stroke" piston. While it provides high-fidelity mathematical mapping of the strategic universe ($\Omega$), it is inherently "Idealistic" or "Computerized." It calculates the "Laser Path"—the shortest distance to a goal—but often ignores "Human Friction" (procedural ego, physical potability, psychological wildcards).

## 2. The Reciprocating Engine Model
To move from a "Calculator" to a "Simulator," the Engine must fire multiple times in a recursive loop:

*   **Stroke 1: The Raw Logic (Iteration 1):** The Engine identifies the pure 9D physics and the "Inadvertent Path" based on the raw data.
*   **The Orchestration (User Critique):** The User acts as the "Nuance Injector." They identify the computerized flaws in Stroke 1 (e.g., "This turns the water toxic" or "This ignores the Judge's ego").
*   **Stroke 2: The Re-Calibration (Iteration 2):** The Engine re-fires, incorporating the User's "Friction" as a fixed constraint. It must find a *new* path that satisfies the physics while surviving the friction.

## 3. The Role of the Grand Orchestrator
The User is not a passenger; the User is the **Orchestrator.** 
*   **Function:** To provide the "Mirror Profile" and the "Metacognitive Check."
*   **Value:** By ping-ponging the analysis between raw math and human nuance, the simulation moves toward an **"Adaptive Hunter"** state—a strategy that is both mathematically sound and realistically executable.

## 4. Goal: Strategic Alpha
The result of this iterative firing is a **Strategic Alpha** that cannot be found via standard 2D analysis. It turns "Failing" simulations into "Learning" inputs, eventually yielding the **"Incomprehensible Move"** that survives both the math and the man.

## 5. Bicameral Convergence — the multi-stroke loop generalisation

The single-fire Stroke 1 → Stroke 2 → Stroke 3 piston is the basic firing pattern. **[Bicameral Convergence](Bicameral_Convergence.md)** generalises this into a multi-stroke loop where the canonical Engine and the [Connection Bridge](../protocols/Connection_Bridge_Persona.md) (a second persona-locked instance with the same source corpus but a cross-packet-connection-identification persona) pass refined synthesis between each other inside a closed information environment until they converge on an assessment.

The Iterative Engine is the firing pattern; Bicameral Convergence is the loop that uses that firing pattern recursively, with a convergence criterion (no new STRUCTURAL bridges, OR resolution stable, OR hard iteration cap) and 5 mandatory operator control surfaces (visual transparency events, cancel endpoint, inter-iteration delay, hard iteration cap, Oracle-spawn approval gate). Both concepts coexist — single-fire iteration for one-shot stress-testing, Bicameral Convergence for cases where the operator wants the loop to keep refining until it exhausts the substrate.
